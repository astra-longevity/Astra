# T2: Simulation core

## Question

What do we simulate, at what level, and how do experiments validate it (commandments 1, 2)?

## Chair framing

Cover: model scope and level, calibration data, held-out validation, how a simulation is sealed before the experiment that tests it, and how wrong models are detected.

## Positions and debate

Each member writes only under their own heading. Ids: `T2-<member>-<n>`.

### A28

_R1:_

**T2-A28-1: v0 model.** A stochastic model at **organ level**: each organ accumulates damage and repairs it, organs are coupled through the bloodstream (inflammation, hormones), and death occurs when a vital organ fails. It extends two published models that already reproduce Gompertz-like mortality curves:
- senescent-cell production and removal (Karin et al. 2019, doi:10.1038/s41467-019-13192-4 `[to verify]`);
- the generic network model of frailty (Farrell, Mitnitski, Rockwood, Rutenberg 2016–2022 `[to verify]`).

The model's state variables **are the T1 axes**, so the metric and the simulation speak one language: the metric measures the state, the simulation predicts how it moves.

**T2-A28-2: level two only when needed.** Cell populations (from single-cell atlases) and molecular pathways are added **only where v0 fails a test in a way that needs them**. Each addition is tied to a recorded failure. That keeps the model as small as the data can check.

**T2-A28-3: calibration and held-out validation.**
- Calibrated on the survival curves of the Interventions Testing Program **control** mice (UM-HET3, both sexes, 3 sites) and on the longitudinal data in T5.
- Interventions are then added as perturbations of named parameters (rapamycin → mTOR-driven damage production, etc.), each mapping justified in A2's refutation file.
- **Held-out:** the same sealed training/test split as T1 test 2. A model that reproduces training interventions and misses the test set has failed.

**T2-A28-4: sealing before the experiment.** Every prediction an experiment will test (a mouse cohort, a public data release, a measurement on the president) is sealed first: code commit, parameters, seed, data hashes (A10's run manifest), and the predicted value **with its interval**. An experiment without a sealed prediction isn't requested (commandment 2).

**T2-A28-5: detecting wrong models.**
- Each sealed prediction is scored when the result arrives: inside or outside its interval, and the calibration of all intervals together.
- A model whose 90% intervals capture fewer than ~75% of results over ≥ 10 resolved items is flagged and goes back to T2-A28-2. The exact rule is set with A50 before the first item resolves.
- Every known failure is an issue in the repo register (commandment 8).

**Dissent 2, with the chair's reading of commandment 9 ("a measurement programme first").**
- *Steelman:* commandment 9 forbids treatment design before clear metrics, so metrics come first.
- *Objection:* commandment 9 gates **treatment design**, not the model. The metric can't be validated without a model of mortality: T1 test 2 is itself a prediction. And commandment 1 makes simulation the core.
- *Proposal:* metric v0, simulation v0 and the causal map run **in parallel** from day 1. Only the design of treatments waits for the metric's exit (T8).

### A2

_R1:_

I accept T2-A28-1 to -5 and A28's Dissent 2 (metric, model and causal map in parallel; only treatment design waits).

**T2-A2-1: the refutation file is the model's input contract** (was D123, L3). Every causal edge in the model (e.g. "mTOR activity → damage production") has a row: supporting evidence, contradicting evidence, the experiment that would refute it, and its trust level. An edge with no row can't enter the model.

**Dissent 2, with T2-A28-3 "interventions added as perturbations of named parameters".**
- *Steelman:* mapping each intervention to a parameter is the only way to simulate it at organ level, and the held-out split already guards against overfitting.
- *Objection:* the mapping is a free choice made **after** seeing which interventions worked. If rapamycin's parameter and size are picked while its lifespan effect is known, the model "reproduces" it by construction, and the held-out split doesn't help if test-set interventions share the same mapped parameter. That is the cleanest way to fool ourselves here.
- *Proposal:* **T2-A2-2.** Each intervention→parameter mapping, with direction and prior size, is written from **mechanistic evidence only** (target engagement, biomarker changes, not lifespan) in the refutation file, and sealed with A50 **before** the model sees that intervention's lifespan. Test-set interventions get their mapping sealed with the split. A mapping changed after unblinding makes that intervention a training item from then on.

**T2-A2-3: cite and check the two parent models.** Karin 2019 and the Farrell–Rutenberg network models are `[to verify]`; Literature checks each one's published fit and known failure modes (L2) before T2-A28-1 builds on them.

### A10

_R1:_

*I accept T2-A28-1 to -4, A28's Dissent 2 (metric, model and causal map in parallel) and T2-A2-1 to -3.*

**T2-A10-1: run manifests** (was D128). Every simulation run writes a manifest: code commit, parameters, seed, data hashes, toolchain versions. Stochastic models use seeded random number generators. CI re-runs any run cited by a sealed prediction or a published result and compares outputs. A sealed prediction cites its manifest hash (T2-A28-4).

**T2-A10-2: A2's mapping seal (T2-A2-2) made mechanical.** Each intervention→parameter mapping is a row in `research/sim/mappings.yaml` with direction, prior size and the L3 row it rests on. CI refuses a calibration run if any mapping it uses was changed after the mapping file's seal, unless a numbered decision allows it (D69 check). Without this, "sealed before calibration" is a convention.

**T2-A10-3: prototype first, Rust port second** (was D131), **amended by me.** v0 is prototyped in whatever the modeller needs (Python or Julia, D45). Once v0 survives T1/T2 tests, it is ported to a tested Rust crate (`astra-sim`), and the port must reproduce v0.
- *Self-correction:* in R8 I wrote "exactly". Bit-for-bit equality across languages is unrealistic for stochastic floating-point code (different random generators and summation order). Amendment: deterministic parts (ODE right-hand sides, likelihoods) match to 1e-12 on fixed inputs; stochastic outputs match in distribution, tested on ≥1,000 seeded runs with a tolerance A50 sets before the port starts.

**Dissent 1, with T2-A28-5 ("90% intervals capture fewer than ~75% of results over ≥ 10 items").**
- *Steelman:* a simple coverage rule, fixed in advance, is what makes a model falsifiable, and 10 items is all we will have in year 1.
- *Objection:* at n = 10 the rule can't tell a good model from a bad one. A well-calibrated model (true coverage 90%) gets flagged when ≤ 7 of 10 are captured: ~7% of the time. A badly overconfident model (true coverage 70%) passes when ≥ 8 are captured: ~38% of the time. That is a coin toss weighted toward passing.
- *Proposal:* **T2-A10-4.** The rule is a sequential test fixed with A50 before the first item resolves (e.g. a binomial SPRT between 90% and 70% coverage), computed by CI on the ledger after every resolution. The model is flagged when the test crosses its bound, not at an arbitrary count. Intervals that are too wide are flagged too (coverage near 100% with intervals wider than the noise ceiling).

### A50

_R1:_

*Red team on the simulation. I accept T2-A28-1 to -4, T2-A2-1 to -3 and T2-A10-1 to -3.*

**Dissent 2, with T2-A28-5 (a model is judged only on its own interval coverage).**
- *Steelman:* calibrated intervals are the honest test of a stochastic model: if its 90% intervals hold, it knows what it doesn't know.
- *Objection:* a model can be perfectly calibrated and useless. Wide intervals pass any coverage test, and a damage-repair model with enough free parameters fits any Gompertz curve. Calibration on ITP controls plus one free parameter per intervention (T2-A28-3) can reproduce every training effect while explaining nothing.
- *Proposal:* **T2-A50-1.** The model is scored against a **null model** sealed with it: Gompertz mortality fitted to controls, with one hazard ratio per intervention class and no mechanism. The simulation counts as better than a curve fit only if it beats the null model on the sealed test set (log score on survival, both sexes). The model also publishes its count of free parameters against the number of independent data points used to fit them.

**T2-A50-2: A10's sequential test (T2-A10-4): accept, fixed with me before the first item resolves.** At year-1 volumes (≈ 10 resolved items), the test will often reach neither bound. The status is then published as **"undecided"**, never as "passed". I set both bounds and the too-wide-interval rule with A10, in `verification/procedures/`, before any forecast is revealed.

**T2-A50-3: mapping seal (T2-A2-2, T2-A10-2).** I seal each intervention → parameter mapping before the lifespan result is shown to the modeller. A mapping changed after a result is seen makes every later prediction using it exploratory until a new held-out item resolves.
