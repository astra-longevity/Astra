# Class-label rules for the R-Metric v0 split (committed before they are applied)

Binding inputs: A28 class-label calls (G158, 2026-10-20), A50 ruling on class-label
sources (`verification/approvals/class-labels.md`, record PR #141), schema rules C4-C6
(`verification/approvals/l1-schema.md`). This file is committed **before** the script that
applies it. `class-labels.yaml` is generated by `class-labels.rb` from this file and the
pinned sources. Nobody edits it by hand. A65 checks that a rebuild gives a byte-identical file.

## 1. Scope

Every distinct value of the `compound` column of `research/metric/v0/split.csv` (41 on
2026-10-20). Combination arms are listed in the split by their single compounds. Each
compound gets exactly one entry.

### 1b. Train scope (amendment 4, A28 ruling G158 2026-10-20)

`train-classes.yaml` labels every distinct value of the `compound` field of
`literature/lifespan/itp/*.yaml` (43 on 2026-10-21), for A67's R-Metric v0 stratum rule 2a
("class present in train"). It is built by the **same script, same rules, same fallback
order → `unclassified`**, the same pinned MeSH 2026 files, but a **separate** train-only
ChEMBL 37 snapshot `class-labels-train-chembl37.json` (A28 option 1). The 41-compound split
snapshot `class-labels-chembl37.json` and its sha256 are **untouched**; `train-classes.yaml`
has its own build sha and a byte-identical rebuild.

- **Train-name canonicalisation (name-only, before any lookup).** The ITP spelling of a
  compound is mapped to the canonical split/alias key through `class-labels-train-names.yaml`
  before the ChEMBL and MeSH lookups (e.g. `ndga` → `nordihydroguaiaretic acid`,
  `17-alpha-estradiol` → `17alpha-estradiol`). Only names of the same substance; chosen from
  names, before any result is applied. The shared `class-labels-aliases.yaml` is **not**
  changed, so the 41-compound split build stays byte-identical.
- **Combination arms** (`metformin + rapamycin`, `rapamycin + acarbose`) match no single
  ChEMBL molecule and have no single primary target, so they fall through to `unclassified`.
  They are emitted as-is and flagged; whether A67 wants a component-level class for the 2a
  join is A28's call, not decided here.

## 2. Source order (first step that gives a class wins)

| Step | Source | Used when |
|---|---|---|
| S1 | ChEMBL release 37 (2026-05-01), REST `mechanism` endpoint, for the parent molecule and every salt form listed by `molecule_form` | always tried first |
| S2 | IUPHAR/BPS Guide to Pharmacology | only if an API key or account is granted. Not available at freeze (login-only since 2026-10-20), so it is skipped and the skip is recorded |
| S3 | MeSH Pharmacological Action (PA), pinned NLM files of one year | S1 (and S2) give no usable record |
| S4 | `unclassified` | no step above gives a class |

Only mechanism records and PA metadata are read. No page or paper that reports a lifespan
outcome is read (C4). No other source may be substituted.

## 3. Step S1: reading ChEMBL

- A **usable record** names a target and an action. These are not usable:
  `mechanism_of_action` = "Unknown", an action type with no target, and non-target entries
  ("Supplement" and similar). A molecule whose only records are like this goes to the next step.
- **Mapping:** the class comes from the ChEMBL target id, through the table in section 6.
  A target that is not in the table is a stop: the script exits non-zero and lists it. The
  table may then change only through a new rules commit, before anything is applied.
- **Multi-target:** if a molecule's usable records cover two or more targets with different
  classes, and ChEMBL does not mark one as primary, the class is `multi-target`.
- **Salt forms:** records on the parent and on its salts are pooled. The entry cites the
  form that carries each record.
- **Name matching (added before the script, amendment 1):** a compound is matched to ChEMBL
  molecules whose preferred name or synonym equals the compound name exactly,
  case-insensitive, with Greek letters spelled out (same rule as S3). Each match is reduced to
  its parent molecule. No fuzzy match, no substructure search. Matched parents and forms are
  saved in a committed snapshot (`class-labels-chembl37.json`, metadata only), and the yaml is
  built from that snapshot, so a rebuild is offline and byte-identical.
- **Aliases (amendment 2):** besides the split name, the lookup (S1 and S3) tries the names in
  `class-labels-aliases.yaml`: other names of the same substance only (INN, acid/salt form,
  spelling). Committed before the script; changed only by a new rules commit.

## 5. Step S3: MeSH Pharmacological Action

- **Files:** NLM MeSH of year 2026, `pa2026.xml` (PA → substances) and `desc2026.xml`
  (descriptor tree numbers), from `https://nlmpubs.nlm.nih.gov/projects/mesh/MESH_FILES/xmlmesh/`.
  The URL, download date and sha256 of each file are written to `class-labels-sources.yaml`
  in the script commit, before the yaml is generated. Raw files are not committed (> 10 MB).
- **Matching:** the substance is matched by exact name or exact entry term, case-insensitive,
  with Greek letters spelled out. No fuzzy match.
- **Admissible PA:** only PA descriptors with a tree number under **D27.505.519**
  (Molecular Mechanisms of Pharmacological Action). Therapeutic Uses (D27.505.954), the
  Physiological Effects branch, and any term on ageing or longevity are ignored (A50 #141 pt 2).
- **Class:** the admissible PA descriptor name, verbatim (for example "Cyclooxygenase
  Inhibitors"). If two or more admissible PAs are not on the same tree path, the class is
  `multi-target`. If one is an ancestor of the other, the most specific one is kept.
  The rule is generic, so no class table is written after seeing the data.
- Each S3 class is added to the vocabulary with `added_by: S3` (allowed before the seal only, C5).

## 7. Output

`class-labels.yaml`: per compound `class`, `source_step` (S1, S1-call, S2-skipped+S3, S4),
the cited record(s) (ChEMBL ids or MeSH UI + URL), `source_date`, `flags`, `proposed_by`,
`approved_by: null`. Vocabulary = every class produced plus `multi-target`,
`no defined target` and `unclassified`.

- `unclassified` compounds stay held-out and never enter stratum a (A28).
- If an IUPHAR key arrives after the freeze, this rule is re-run as a new version and
  published with a label and stratum diff (A50 #141 pt 4).

## 8. Train build: overlap consistency check (amendment 4, A28 binding condition)

`train-classes.yaml` (§1b) is built from its own train-only ChEMBL 37 snapshot, fetched at a
different time from the sealed 41-compound snapshot. Five compounds are in both snapshots:
**canagliflozin, captopril, metformin, nicotinamide riboside, rapamycin** (plus their
aliases). The train build asserts that each of the five gets the **same `class`** in
`train-classes.yaml` as in the sealed `class-labels.yaml`. The build records both snapshots'
`fetched` date and `endpoints`, prints the five-row overlap table, and **aborts** on any
mismatch — a mismatch would mean a silent within-release-37 drift between the two fetch times,
which is flagged to A28, not papered over. A65 approves `train-classes.yaml` as a seal input
alongside `class-labels.yaml`.
